
#### Skills

- **Without `context: fork`:** `allowed-tools` = _"Auto-approve these tools, but keep everything else available."_
    
- **With `context: fork`:** `allowed-tools` = _"Run in an isolated subagent and **only** allow these tools."_

In Claude Code, the main agent's allowed tools and permissions are determined by a combination of **settings files, command-line flags, permission modes, and interactive `/permissions` rules**.

### Where Main Agent Permissions Are Defined

#### 1. Configuration Files (`settings.json`)

Claude Code merges rules from several hierarchical `settings.json` files. The main agent checks these files for `allow`, `deny`, and `ask` arrays:


- **User Level:** `~/.claude/settings.json` (Applies globally across all your projects).      
    
- **Project Level:** `.claude/settings.json` (Shared with your team via git).
    
- **Local Project Overrides:** `.claude/settings.local.json` (Personal settings for the current repository).
    
- **Enterprise / Policy Settings:** Managed admin policy files that cannot be overridden.

**Example structure in a `settings.json`:**

JSON

```
{
  "permissions": {
    "allow": [
      "Read",
      "Grep",
      "Glob",
      "Bash(git status)"
    ],
    "deny": [
      "Bash(rm -rf *)"
    ]
  }
}
```

#### 2. Interactive CLI Commands & In-Session Approvals

- **/permissions:** Running `/permissions` inside the terminal shows all active rules and the exact file they were loaded from.
    
- **Interactive Prompts:** When Claude requests a tool, clicking **"Yes, don't ask again"** automatically appends an entry to your project's local permissions list.

#### 3. Permission Modes (`defaultMode`)

The default mode dictates how tools that aren't explicitly pre-approved are handled:  

- **`default` / standard:** Prompts you for approval whenever Claude tries to modify files or run bash commands.
- **`acceptEdits`:** Automatically allows read operations, file edits, and common git commands without prompting.
- **`plan`:** Locks down tools so Claude can only read files and research, preventing writes or code execution.
- **`dontAsk`:** Only allows tools listed in your pre-approved `allow` list; anything else is automatically denied instead of prompting you
- **`bypassPermissions`:** Grants full execution access without prompting
#### 4. Runtime Flags

You can temporarily override or add allowed tools when starting a session:

Bash

```
claude --allowedTools Read Edit Bash
```

### Built-in Native Tools Available to the Main Agent

By default (unless explicitly restricted by `deny` rules or isolated modes), the main agent has access to Claude Code’s full suite of native tools:

- **File Operations:** `Read`, `Edit`, `Write`, `Glob`, `Grep`
- **Execution:** `Bash` 
- **Agent / Subagent Delegation:** `Agent`, `Skill`
- **Web & Search:** `WebSearch`, `WebFetch`
- **MCP Integration:** Any tools provided by connected Model Context Protocol (MCP) servers.

/memory is a built-in command for managing memory between sessions:
- Opens the CLAUDE.md file for editing, alowing you to save notes, preferences, and context
- Information persists across sessions and is automaticaly loaded on startup
- Useful for storing project conventions, user preferences, frequently used commands, and current work context
