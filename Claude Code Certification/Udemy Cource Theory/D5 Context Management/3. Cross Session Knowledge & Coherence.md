
# The Scratchpad Pattern - A Durable Memory Slot

- Scratchpad File - a plain text file like NOTES.md that holds durable cross-session state for an agentic coding workflow.
- Cross Session Knowledge - decisions, conventions, and prior context that should persist across separate sessions in one repo
- Decision Log - a scratchpad subsection recording architectural choices and rationale so sessions do not re-litigate them.

#### What Goes Into the Scratchpad

- Decisions - choose postgres over Mongo 
- Dead Ends - dropped the GraphQL layer, too slow
- Conventions - snake case for all table names
- Task State - in progress auth, next billing

#### What Stays Out of the Scratchpad

- Code - code lives in the codebase, not the scratchpad. Duplicating it creates drift and stale copies.
- Credentials - secrets and API keys should never appear in any plain text file commited to repo
- Private User Data - personal or sensitive data

#### Loading at Session Start

- List it first - name it amont the first files to read in CLAUDE.md
- Enforce it - an explicit hook or instruction makes the read a rule
- Without a rule , agents skip the file and lose context


# Designning a Healthy Scratchpad  - Hygiene and Limits

- Scratchpad Hygiene - pruning resolved entries, structureing the file consistenly, and avoiding stale notes that mislead the agent
- CLAUDE.md vs Scratchpad - CLAUDE.md holds stable rules; the scratchpad holds evolving state. On conflict CLAUDE.md winds
- Pruning Policy - a defined rule for removing resolved entries, archiving completed state, and capping file length.


#### Length Discipline: Cap and Prune 

- Set a cap - a line or word limit that triggers a pruning pass
- Remove on resolve - delete resolved entries as soon as they close
- Archive state - move completed task state out instead of pilling it up

#### Recommended Strucutre Block

- Dated Entries - timestamp entries so stale notes are easy to spon and prune
- Decision Log - architectural choises and retionale; reraly pruned
- Current State Block - what is in progress now; rewritten, not appended
- Open Questions - unresolved items; removed once they are answered

#### Multi-Devekoper Coordination

A scratchpad commited to git becomes a shared resource across the team

- Shared Visibility - developers read each other's state and decisions
- Conflicts as signal - merge conflicts flag concurrent work on a task
- Clear ownership - agree on who owns the current-state block when pairing

# Why Delegate Discovery to a Subagent

- Subagent Delegation - spawning a child agent to handle verbose onvestigation, returning only a focused summary to the parent
- Discovery - finding relevant files, documentation, or context inside a large codebase or knowledge base
- Disposable Context - a subagent's context window. Discarded after it returns, so verbose state never reaches the parent

#### Inline Discovery vs Delegated Discovery 

- Inline Discovery - the main agent reads files directly. Every grep result, dead end, and file body lands in its context, crowding out task-relevant state
- Delegate discovery - a subagent reads the files and returns only is finding. The main agents context stays clean; the verbose state is thrown away with the child 

#### When Delegation Pays Off

- Codebase Survays - milti file investigation that read many candidates before narrowing to the right one
- Doc Investigation - searcgin long reference docs or changelogs where most pages are not relevant
- Multi Step lookups - tasks that chain iserveral searches, production layers of intermidiate results

#### The Delegation Trade 

- Cost sode - a subagent run adds latancy and token spend 
- Benefit side - the main agent avoids pollution and stays on task
- Scales up - net benefit grows with discovery complexity

# Delegation Mechanics - Prompts, Returns and Failure Modes

- Return contract - the explicit shape of the response a subagent produces to keep the parent's context clean
- Trust Boundary - the rules that the parent treats subagent output as a hypothesis to verify, not truth

#### Subagent Prompt Design 

- Say what to find - state exactly what the subagent must locate 
- Set the scope - name which directories, file , or topics to check 
- Say what to skip - list what to ignore to prevent scope creep


# Long Conversation Coherence

#### The Model's Own Context Awareness

- An injected token budget tag states how much room the model has
- After a tool call, a system warning can flag that context is filling
- These cues let the model wrap up before it truncates
- The signal guides behavior; it's not a hard guarantee against overflow

#### How to compact the history

- Full summarization
- Selective summarization - keep key decisions, drop small talk and filler
- Sliding window - keep the last N turns verbatim with a summary header

#### Coherence Techniques for Long Sessions

- Session Header - open each call with a brief prior-context sumamary
- State tracking - have the model keep a JSON object of goals and decisions
- Goal anchoring - restate the user's original goal at each turn.


# Server Side Compaction

#### Server-Side vs Your Rolling Summary

- Server-side compaction - you opt in with a beta header and a context-management strategy, then set the trigger threshold. The planform runs the summary at that point for you.
- App-Level rolling summary - your own code, watches the length and calls the model to summarize. You own the timing, the prompt, and that gets kept

#### Trade-Offs

- Less to build - compactoin runs inside the platform, so you skip writing code
- Less Control - you give up fine control over what is kept
- Not free - the summary still has limits and a cost

#### The Foundations Catch

- A fact not captured in the summary is simply gone from context
- Exact numbers, IDs, and code can quitly drop out
- The model can't recover what the summary left behind
- So never treat the transcript as your only cope of something important


#### Keep State Outside the Chat

- Write durable facts to a file or database as you go
- Re-read that store instead of trusting old turns
- Let compaction handle bulk while you store holds the essentials
- This pairs naturally with the memory tool.
