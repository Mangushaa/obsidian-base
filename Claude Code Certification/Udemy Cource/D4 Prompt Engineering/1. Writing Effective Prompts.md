# The System Prompt

- System prompt - instructions set before the human turn.
- User turn - the human message in each exchange
- Persistent Context - information that applies to every run

#### Section of a System Prompt

- Role - who the model is: its expertise, professional identity, and tone of voice
- Context - domain knowledge, policies, and data the model needs throughout the session
- Instructions - what the model should do: task behaviors, response format; and workflow steps
- Constraints - what the model must never do: prohibeted topics, length, tone rules.
- Examples - sample inputs and outputs that illustrate the rules stated above.

#### Ordering sections for clarity

- role
- context
- instructions 
- constraints
- examples

# Role Assignement, Persona, and Context

- Role Asignment - tell the model what expertise to adopt
- Persona - a named identity with it's own voice. E.g Aria, friendly guide
- Context injection - place real data into the prompt


#### How role shapes model behavior

A role assignement is no decoratove - it changes vocabulary, reasoning depth, and tone. Role assigment is the fastest lever for aligning behavior with your use case.

Persona extends role with character and communication style

#### Testing role and context consistency

- Topic switches: does the role hold when the user goes off-script?
- Context retrieval: does the model use injected data over training priors?
- Persona pressure: can users overrode the assigned identity
- Baseline expected outputs before deploying to production


# Using XML tags to structure complext prompts 

- Claude is trained to respect XML boundries reliably
- Prompt injection - an atack where milicious input overrides developer instructions. XML tags help lavel data vs instructions, but are not primary defence.
- Tag Consistency - using the same tag names throught a prompt and across related prompts. Consistent naming reinforces the structural signal Claude uses to parse.

#### Why XML beats plain delimiters

- Plain text delimeters like dashes of headers are ambiguous. Claude may misread them as content rather then structure signals. Xml tags have unambiguous open and close syntax.
- The model was trained on structured documents, not ad-hoc separators.

#### Standart tag conventions

- {instructions} - wraps the task directive the model should follow.
- {context} - holds the ackground information the task needs.
- {examples} - contains few shot demostrations of the desired output 
- {output_format} - specifies the structure and format you expect back.

#### Tag Naming Best Practices

- Be descriptive - name tags by content type: <customer_data> is clearer then a vague <_data> tag.
- Stay consistent - use the same tag names for the same roles across every prompt.
- Avoid Deep Nesting - one or two is enough. Deeply nested tags get hard to read
- Match your schema - if you use <document_> in one prompt, reuse that same tag in every prompt.
