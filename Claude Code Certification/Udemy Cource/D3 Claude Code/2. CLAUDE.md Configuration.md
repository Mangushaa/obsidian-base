
# Three Level CLAUDE.md Hierarchy

- Managed policy - org-wide CLAUDE.md at a system path.
- User Scope - ~/.claude/CLAUDE.md - personal preferences across all you sessions. Loaded after managed policy, can't be. excluded
- Project scope - ./CLAUDE.md or ./.claude/CLAUDE.md at the repo root. Project instructions.
- Local - CLAUDE.local.md - should be gitignored

Claude concat all this.

# Precedence rules and conflicts resolution

- Load Order - CLAUDE.md files are concated from broadest (managed) to most specific (local). On a conflict (opposite things described in diffirent scopes) there is not reliable precedence, so claude can follow any of them.
- Complementary instructions - instructions on diffirent levels that do not conflict. All apply simultaniously

#### Seeing which instructions are active

- Run /memory to see loaded memory files, or /context to inspect what's loaded


# Subirectory CLAUDE.MD Files and Scoped Instructions

- Subdirectory Config - a CLAUDE.md file placed inside a specific subfolder. Claude Code lazy-loads it when it reads a file inside that rdirectory.
- Directory-Scoped CLAUDE.md - instructins scoped to a directoy by placing CLAUDE.md inside it. No registration step needed. The file location is scope.
- CLAUDE.md Hierarchy - project-level config and subdirectory config work togather. Subdirectory files add rules. Then don't erase parent instructions.


# Excluding Files and Content

File exclusions lives in the permissions block of settings.json as Read deny entries

```
{
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(secrets/**)"
    ]
  }
}
```

settings.json same as CLAUDE.md lives in same scopes: Managed, Local, Project, User

Deny on any level blocks access, even if allow defined in any other scope.


**NOTE:** If claude runs python subprocess that access that file, that process will have access tp that file. Only tool call from agent itself is blocked. 


# Instructions Design What Claude Really Reads and Follows

- Use clear header sections: Language, Style, Testing, Git, Security
- Bullet points outperform paragraphs - one directive per line
- Group related rule sso context pressure hits a whole category at once.
