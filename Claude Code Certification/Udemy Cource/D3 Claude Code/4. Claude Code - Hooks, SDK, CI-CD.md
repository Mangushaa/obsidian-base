
- Hook registration - declaring a hook in the settings file by naming the lifecycle event and the command or script to run
- Exit code convention - exit 0 continues, exit 2 blocks and feeds stderr to claude, and any other non-zero code is a non-blocking error that is logged while the action proceeds.
- Hook timeout - the time claude waits for a hook to finish. A slow hook can stall the session until time out. 

#### Registering hooks in settings

- Each entry specifies the lifecycle event and the command to run
- Commands can be inline shell one-liners or paths to external script files
- Multiple hooks for one event run in parallel - don't rely on order
- Keeping complex logic in script files makes hooks easier to test and version control

#### Writing a PreToolUse shell script

- Context arrives as JSON on stdin - tool name, input, session
- Env vars are for path resolution not tool data
- Inspect the name or path and apply policy
- Exit 0 allows, exit 2 blocks
- A stray exit 2 silently blocks every call, so test each path

# Real-World Hook Applications

- Auto-Format Hook - runs a formatter after any file write
- Safety Net Hook - blocks destructive Bash before it runs
- Audit Log Hook - records every tool call to a log file 

# The Claude Agent SDK

- Claude Agent SDK (Claude Code SDK) -  controls full agentic sessions: multi-step tool use, file edits, shell commands, and streaming output. SDK manages the session loop, and your code just provides prompts and handles events
- Claude API (Direct) - make individual model calls: send prompt, get a completion. No session state, no tool orchestration unless you build it youself. Best for single-turn tasks or custom agent frameworks you manage

# Claude Code in CI/CD Pipelines

- claude -p  - run claude code in non-inteactive mode (get a task and exit after completion)

#### Why -p is Required in CI/CD

- Without -p, Claude Code enters inteactive mode and waits
- CI/CD runners have no terminal so the job blocks
- The -p flag runs the agentic loop non-interactively and exists when done
- It returns a status code the pipeline can act on
- The -p flag bridges claude code and automatio


#### The -p Flag and it's Companions

- -output-format json - return json output; stream-json emits events live
- -allowedTools scopes which tools the run may invoke
- -resume and -continue pick up a prior session
- Exit code 0 means sucess; non zero signals error
- Togathe these flags make headless run predictable
