# Errors 

- Tool Error - external to model error 
- Reasoning Error - internal to model, model produces a wrong plan or misreads a result. Retry with identical input fails again
- Environment Error - network, db, or file system error.

## Retry policies

- Tool Error - retry with backoff, or switch to fallback tool
- Reasoning Error - modify the prompt, or correct context, do not retry
- Environment error - ofter resolved by waiting and retry

# Error detection

- Silent Failute - output looks succesful but is wrong, incomplete, or corrupter. No error signal raised
- Validation Gate - a checkpoint that inspects step output against criteria before letting execution continue
- Error propagation - a failure in one stage flows downstream, causing cascading failures across pipeline.

## Detection Strategies

#### Output Validaiton

Validate agent output

1. Schema checks - required fields present (correct types, no enexpected nulls)
2. Range Checks - for numbers, strings
3. Completeness check - all required section populated, not truncated response.

- Transient (Temporary) errors - rate limit, network issues, 500, timeouts
- Persistent errors - retry will not fix: invalid input, permission denied, reasoning errors

**NOTE:** Uncapped retries accumulate cost and latancy. So it's mandatory to set retry limit.

# Fallback chains and Graceful degradation

- Fallback Chain - ordered sequance of alternatives tried when the primary action fails, ending escalation
- Graceful Degradation - returning a useful but incomplete result while explicitly signaling the reduced quality downstream.
-  Silent Degradation  - returning a degradeted result without signal about it. Downstream wrongly treats as full success.


#### Fallback chain

- Each step is prevalidated alternative.
- Steps execute in order, each one only if prev one failed
- The chain always ends with result, or escalate.

If downstream coomponents sees that result contains defradation flag it's should adjust confidance or riuting.

## Fallback chain antipatterns

- Untested fallbacks - deploying a fallback never validated in production 
- Silement masking - a fallback chain hides degradation from downstream components produces silent failures that compount undetached across pipeline.

# Escalation trigger design

- Human in the loop (HITL) - human is taking action in the agent path at defined checkpoints
- Escalation trigger - a cindition that pauses an agent for human review
- Programmatic enforcement - code layer mechanism that enforce constraints no metter what model outputs

## HITL valid triggers
- High stakes - data deleteion, financial transaction etc.
- Irreversable
- Low confidence - model unconfedence exceed some threshold
- Scope boundry - task drifts beyond authorized bounds or expected parameters
- Retru exhausted

## Invalid triggers: Over Escalation

- Low-Stakes, Reversable 


# Interruption Points and Review Workflows

- Interruption Point - a defined point where agent pauses for human input
- State management - persist progress and decisions outside the context window

## Where to place interruption points
- Before irreversible actions - the most critical placement, prevent uncorrectable errors
- At phase boundaries
- On anomaly detection - unexpected inputs, unusual patterns, out of range values


#### Designing handoff message 

Handoff message is message that is passes to human when agent pauses for human intervention

- Include what agent was doing - context the reviewer needs to orient quickly
- What decision is required - a specific question not open ended one. 
- State the consequences - outcomes of what will happened if decision will be approved/denied.

#### Handoff message components
- Context - what was agent doing
- Decision required - what needs to be approved, decided
- Consequences - what will happened if will be approved/denied
- Deadline - when does review expire and what is happens at timeout.

#### Sstate preservation during interruption

- Do not rely on in-context state - context can be truncated or the session can end
- Persist task progress
- Persis agent decisions

## Sync vs Acync escalation

- Sync - agent fully stops waiting for human response
- Async - agent queues the review and continue work on other no related to decision branches
