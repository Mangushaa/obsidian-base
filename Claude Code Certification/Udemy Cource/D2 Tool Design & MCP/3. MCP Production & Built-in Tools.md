- Streaming responses open a long-lived SSE connection for event delivery

# Letting Servers Make LLM Calls Through the Client


- Sampling - an MCP feature where a server asks the client to make an LLM call and return the result
- Sampling Handler - a callback in the client that receivers sampling requests, calls LLM, and returns the response
- HITL (Human in the loop) - an optional gate where the client pauses for user approval before forwarding a request to the LLM

**NOTE:** Main sampling purpouse is splitting responsibility, MCP server do not hold and model configurations/api keys that is present in client, it's responsibility strictly invoke related tool, 

**Flow**:
- MCP sends createMessage(messages) -> Client
- Client Optionally asks for user approve
- Client calls LLM with messages provided by MCP client.messages.create()
- Client packages a result and return it to MCP server.

Responsibilities:
- MCP Server controls -message content, system prompt, model preferences it sends in createMessage requests
- Client controls - which actual model is used, whether credentials are shared, and thetther human approval is required

#### Model preferences in sapling request

- Intelligence hint: low, medium, or high
- Speed hint - how quikly response is needed
- Model name suggestions listed in priority order


# Notifications, Roots, and Progress

- Progress notification - an MCP notification sent during a long running tool call to report incremental status. Keeped the client informed without blocking final result.
- Roots - a list of filesystem paths or URIs the client declares to a server, advising the scope it should work within. Advisory not enforced????????
- Log Notification - an MCP notification carrying a serverity level and message string for server-to-client diagnostic during execution.


#### Progress Notification Fields

- progressToken - an opaque token from the original too cal, used to match progress updates to theor parent operation.
- progress - a numeric value showing how far along the operation is, relatove to the total field if provided
- total - the optional target value for progress.

**NOTE:** if clients wants to get tool execution progress notification it sends progressToken in tool execute requests. If it's not present it means client do not want to track progress. Otherwise server calls *report_progress(progress, total)* in each meaningful checkpoints.



#### Log Notifications vs Progress Notifications

- Log Notifications - Carry text messages with serverity levels. Designed for diagnostics and debugging. Clients may display, filter, or store them
- Progress Notifications - carry numeric progress and total values tied to a specific operation token. Designed for UI progress bars and user feedback.

# Tool Boundaries and Least Privilege

- Access Scoping - defining explicit boundries on what data and operations each MCP server may reach.
- Least Priviliage - each tool gets only the permissions its function requires, ,minimizing blast radius if misused.
- Input Sanitization - validating and cleaning arguments at the server boundary before they reach any downstream system

**NOTE:** MCP tool should have permission and logic boundries for single task.


#### Scoping mechanisms in MCP

 - Schema constraints - strict argument types and enum values let the server reject out-of-range inputs before any handler runs.
- Root Grants - MCP roots restrict which filesystem paths or URI prefixes a tool may access at the protocol level.
- Server-Side auth - authorization checks in the handler verify called identity and permissions before touching a resource.

# MCP in Production Auth and Reliability

#### Authentication Patterns

- OAuth 2.1  - MCP's reccommended optional mechanism for HTTP servers.
- API keys - simple shared secrets in request headers. Easy to implement but lack per-user identity, scope granularity, and standart revocation
- mTLS - Mutual TLS authenticates both parties via certificates. Strong for service-to-service but add certificate management overhead.

#### Reliability practices

- Health endpoints
- Graceful detradation
- Timeout Enforcement

- Specific schema needed not provided by antrophic built in

- Regulated data - since built in runs in antropc infra if data is regulated and can live your network built in tool needed
