
The Datadog Agent is open source software that runs on your hosts. It is the service that listens for and collects events, logs, and metrics from hosts and sends them to Datadog to be processed and displayed.

The Agent can be installed in many environments, as described in the [Datadog Agent documentation](https://docs.datadoghq.com/agent/).

The Agent is comprised of the following parts:

- The Collector is in charge of running checks and collecting metrics
- The Forwarder sends payloads to Datadog
- The Application Performance Monitor Agent collects application traces
- The Process Agent collects live process information

The Agent ships with many integrations beyond system-level checks and can automatically run checks on popular services such as Nginx, PostgreSQL, and Redis. All Agent checks can be configured using well-documented YAML files that are installed with the Agent.

# Agent configuration

The Agent can be configured by using several the following methods:

- Remote Configuration
- Environment variables
- The `datadog.yaml` file

These methods are listed in the order of precedence. This means that if a configuration is set by using environment variables, it will override the configuration set in the `datadog.yaml` file. If a configuration is set by using Remote Configuration, it will override both environment variables and the `datadog.yaml` file.

Details on the Agent configuration files and a link to a sample `config_template.yaml` file can be found in the [Agent Configuration Files](https://docs.datadoghq.com/agent/configuration/agent-configuration-files/) documentation.

# Remote Configuration

Remote Configuration is a Datadog capability that enables you to remotely configure and change the behavior of Datadog components (such as Agents, tracing libraries, and Observability Pipelines Workers) deployed in your infrastructure, for select product features.

When Remote Configuration is enabled on the Datadog Agent, it periodically polls the configured Datadog site to determine whether there are configuration changes to apply to your Remote Configuration-enabled Agents or tracing libraries.

For a list of features that support Remote Configuration and steps to enable it, see the [Remote Configuration](https://docs.datadoghq.com/agent/remote_config/) documentation.

# Agent Commands

The Agent `status` command displays the Agent's status, including the checks it's running, the logs it's collecting, and more.

The Agent `config` command lists the resolved values of every Agent configuration parameter. It includes default values and those set by using environment variables.


# Agent configuration 

The Datadog Agent is configured by editing YAML files. On Linux systems, these files are located in `/etc/datadog-agent` by default. These files were created when you installed the Agent.

You must restart the Agent for configuration changes to take effect.


The Agent doesn't collect logs by default. It's up to the user to determine whether they want to collect logs, which logs they want to collect, and to tell the Agent where to find them.


# Configure Logging

Logging is not enabled by default, so you will edit `datadog.yaml` to enable logging on this host.

1. In the IDE, expand the `datadog-agent` directory and open `datadog.yaml`.
    
    Find the section titled **Log Collection Configuration**.
    
2. Locate the line with `# logs_enabled: false`.
    
    Un-comment the line by removing the leading `#` and space characters and replace `logs_enabled: false` with `logs_enabled: true`.
    Most of Storedog's services are running in Docker containers. The Agent won't collect these logs by default, so you must enable this feature.
3. Below the `logs_enabled` line that you un-commented in the previous step, find and un-comment `logs_config`.
    
4. Un-comment `container_collect_all` and set it to `true`.

# Configure Docker logs 

The Agent collects metrics, events, and logs from containers by reading the Docker daemon socket, `docker.sock`. This also gives it full access to metrics about the Docker daemon.

The Agent runs as the system user `dd-agent` with only the permissions necessary to perform its Agent duties. By default, Docker resources are only accessible to members of the `docker` group. The solution is to add the user `dd-agent` to the group `docker`.


# Apm Traces


Out of the box, the Datadog Agent is ready to accept APM traces from instrumented applications on localhost. However, containers run on their own network. Next, you'll configure the Agent to accept traces from other networks.

1. Open `datadog.yaml` in the IDE and find `apm_config:`. Un-comment this parameter.
2. Under `apm_config:`, find `apm_non_local_traffic`. Un-comment this parameter and set it to `true`.


# Agent checks

The Agent comes installed with dozens of Integrations called "checks." These are Python scripts that the Agent runs to collect metrics, events, and logs from the host and services running on it.

The Agent runs many checks automatically, such as disk, cpu, memory, and more. Others require a little configuration. In this lab, you'll see where all the checks live in the host filesystem, and configure two yourself: Redis and PostgreSQL.


The Datadog Agent runs a core set of checks by default. These include cpu, disk, memory, uptime, and more. When you run the `datadog-agent status` command, these appear in the **Collector > Running Checks** section of the output.

Each of these checks has a corresponding configuration file located in a subdirectory of `datadog-agent/conf.d/`.


To see a concise list of the checks the Agent is running and their configuration file paths ```datadog-agent configcheck```
You should see the **Configuration source** for each of the checks. Notice the subdirectory and filename, such as the following for **disk check**:
```
=== disk check ===
Configuration provider: file
Configuration source: file:/etc/datadog-agent/conf.d/disk.d/conf.yaml.default
Config for instance ID: disk:30d0851c06e1189e
use_mount: false
~
===
```

All the checks in `datadog-agent/conf.d/` are known as Agent-based integrations, a subset of the massive Datadog integration ecosystem. As such, you can find documentation for all of them in the [Integrations documentation](https://docs.datadoghq.com/integrations).

If there is a check that you would like the Agent to run that is not provided by a Datadog integration, you can create your own. See the [Writing a Custom Agent Check documentation](https://docs.datadoghq.com/developers/custom_checks/write_agent_check/) for details.
